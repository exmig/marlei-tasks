# In Tasks aus Boot abgeschrieben und an drei Stellen geaendert: der
# Modulkopf (in Boot ist der blinde Fleck der Netzstart, in Tasks die
# Frage, ob man ueberhaupt durchkommt), die Umgebungsvariable ohne
# PXE_-Praefix, und
# die Portliste -- zwei Zeilen statt neun. Der Rest, also die ganze
# Ableserei ueber ufw und systemd samt beider is-active-Fallen, ist
# byteweise dieselbe.
#
# Seit dem 07.09.2026 kommt eine vierte Aenderung dazu: ports(), das den
# Port der Oberflaeche einsetzt. Boot braucht das nicht -- dort steht die
# 80 fest. In Tasks laeuft die Oberflaeche auf einer Maschine mit Boot
# auf einem eigenen Port, und die Karte muss den nennen, den es wirklich
# gibt.
#
# Seit dem 19.09.2026 eine fuenfte, und sie ist die groesste: **die
# Windows-Seite.** MARLEI Tasks laeuft dort, MARLEI Boot nicht -- ein
# Bootserver bootet keine Rechner von einem Windows aus. In Tasks kommen
# deshalb dazu:
#
#   SYSTEM           die Weiche, und als Variable, damit die Testreihe
#                    beide Seiten auf derselben Maschine prueft
#   WINDOWS_PORTS    zwei andere Zeilen: die Anwendung selbst statt des
#                    nginx (es gibt dort keinen) und der Remotedesktop
#                    statt sshd -- man sperrt sich anders aus
#   "oberflaeche"    ports() setzt den Port an der Zeile MIT DIESEM
#                    MERKMAL ein und nicht an der mit dem Namen "nginx";
#                    sonst nennt die Karte unter Windows wieder die 80
#   an: None         die dritte Antwort, "nicht feststellbar". Fehlt der
#                    Schalter in der Registry, waere "also an" ein Schluss
#                    aus der Vorgabe des Systems und keine Auskunft
#
# Die Ableserei selbst steht NICHT hier, sondern in webui/windows.py --
# siehe die Anmerkung unter dieser Liste.
#
# Damit ist diese Datei kein naher Kandidat fuers echte Teilen mehr: Es
# waere nicht mehr PORTS, das herausmuesste, sondern die halbe Datei.
# Abgeschrieben unter Aufsicht, und die Aufsicht zaehlt jetzt mehr.
angepasst  webui/firewall.py

# Die erste Haelfte war byteweise Boots: last, kerne, cpu, speicher,
# netz -- Zahlen aus /proc, die auf jedem Server dasselbe beantworten.
# **Seit dem 19.09.2026 stimmt das "byteweise" nicht mehr**, und die
# Korrektur gehoert hierher statt in eine Erinnerung: In Tasks traegt
# jede dieser fuenf Funktionen oben eine Weiche nach Windows, dazu die
# Variable SYSTEM. Die Frage, die sie beantworten, ist dieselbe
# geblieben; der Weg zur Antwort ist es nicht mehr.
#
# **Eine Zahl faellt dort ganz weg: das Lastmittel.** Windows fuehrt
# keins -- kein fehlender Wert, sondern ein Begriff, den das System nicht
# hat. In Tasks gibt last() unter Windows deshalb nichts zurueck, und die
# Kachel verschwindet mit. Fuer Boot ist das ohne Belang.
#
# Die zweite Haelfte ist ERSETZT, nicht gestrichen: Boot liest dort die
# offenen TCP-Verbindungen auf 80 und 2049 und sagt, wer gerade sein
# Wurzeldateisystem zieht. In Tasks zieht niemand etwas -- an ihre Stelle
# tritt dienst(): seit wann laeuft dieser Dienst, und was braucht er
# selbst. Dazu dauer_dativ(), das es in Boot nicht gibt.
angepasst  webui/auslastung.py

# Dieselben vier Kacheln in beiden. Was in Boot darunter steht (das
# eigene Stueck _laufend.html mit den laufenden Uebertragungen), gibt es
# in Tasks nicht; stattdessen die Zeile ueber den Dienst selbst.
#
# Seit dem 19.09.2026 sind es in Tasks unter Windows drei Kacheln: Das
# Lastmittel gibt es dort nicht. Und der Satz darunter -- "Auslastung
# nicht abfragbar" -- hat zwei Fassungen und eine andere Bedingung: Er
# fragt jetzt den Speicher mit. **Ohne das stand er unter Windows beim
# ersten Aufruf da**, weil Lastmittel und erste Prozessormessung beide
# fehlen, und zwar aus harmlosen Gruenden. Der Speicher kommt beim ersten
# Aufruf mit; fehlt AUCH er, ist wirklich keine Quelle da.
